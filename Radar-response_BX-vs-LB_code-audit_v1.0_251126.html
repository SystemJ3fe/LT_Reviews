In plain terms

In plain terms: three response templates reviewed. Rendering a Radar response rebuilt from the values Instanda stored reproduces those values exactly for both products, so the mapping is wired correctly. The BX NB/MTA response 1.0.0.0 still has no commas between work areas (fixed in the renewal response and in LB), so any multi-note response is unparseable, if that version is still deployed: the payloads suggest the renewal response is used for NB and MTA as well. A null number from Radar breaks all three. The products differ in how they return the renewal target ratio (number vs text) and the submission ID (different key; the BX value appears never to be stored).
