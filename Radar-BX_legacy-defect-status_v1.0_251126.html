In plain terms

In plain terms: the renewal templates have had real fixes since May. The response comma bug (PRC-07), the ratio type (PRC-06), the claims precedence bug (PRC-01), the claim ID default (PRC-02b) and the header character (PERF-03) are fixed in the renewal templates, and the day-one uplift now comes from one attribute for every period. The NB/MTA templates are almost untouched: the NB/MTA response still has the comma bug, and the NB/MTA request still has every lineage defect. Which of them is live is still an open question (CQ-1). Three fixes followed the May recommendations literally and inherited their gaps: | size inside if does nothing on DotLiquid, so empty arrays are now sent (PERF-01). The nested claims gate still drops claims when the period ID is unexpected (PRC-01). The claim ID default reads an attribute no payload carries (PRC-02b). The headline May defect PRE_7209 has not been changed and cannot be confirmed with today's payloads, because neither attribute name carries a renewal adjustment. The four upstream items (PRE_7200, PRC-04, INT-NEW-1, INT-NEW-2) were Logic Apps findings; since the move to Function Apps they need one captured request each.

Lessons for the fix process

  • Fix text must be proven on DotLiquid before it is handed over. The May | size recommendation was tested on LiquidJS, where filters inside if work; on DotLiquid they are ignored. The W3 side-by-side examples are proven on DotLiquid 2.3.260 for this reason; host confirmation is still needed.
  • A fix should be checked at every site and in every sibling template. PRC-07 was fixed in the renewal response only; the NB/MTA response, same pattern, was not touched.
  • The same version number on different content (NB/MTA response 1.0.0.0, 2025 and 2026) means a version alone does not identify a file; record the SHA as the W3 scope tables do.
