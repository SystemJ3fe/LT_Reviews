In plain terms

In plain terms: the Radar templates for both products work on real data under two unconfirmed host conditions: full whitespace trimming (syntax level 22) and a base64 decode step before rendering. Both conditions should be confirmed with two short host tests before anything else. Beyond that, the BX templates read four attributes that do not exist (amended-excess flags, commission rate, agent, BI months type), so information is silently left out of the BX rating request; LB reads the right attributes for agent and commission rate but has its own dead gate (residents-association flats). Shared defects (no JSON escaping, raw numbers, empty capstones, claim IDs) need one fix each, applied to both products. The response mapping is proven correct by round trip for both products; the BX NB/MTA response still carries the work-area comma defect, and it is unclear whether it is deployed.

  1. Before any change: host tests HT-W3-1 (whitespace) and HT-W3-2 (base64 decode); answer CQ-1 (which BX templates are live).
  2. Next versions, all products: F1 separator pattern, F2 JSON escaping (after the W2a D1 decision), F3 numeric defaults, F10 capstones/trades, F9 size tests.
  3. Next BX request versions, with Pricing sign-off: F4 amended excesses, F5 commission rate, F6 agent, F7 file key, F12 BI months type.

Decisions and limits

  • Performance is out of scope for this report. 2 items are carried to the performance round (tagged perf-candidate): bx-req / bx-rreq: Capture plus marker removal inside the premises loop (perils, excesses per premise) and the peril-enrichment loop nested in it.
  • Host configuration. DotLiquid version, syntax level, naming convention, culture, time zone and the pre-render steps (base64 decode, policyPeriods assembly) on the Function App are not confirmed. Findings marked Verify depend on them; the recommended fixes work under any setting except where the Risk column says otherwise.
  • Engine difference. The level-20 whitespace result (RAD-BX-01, RAD-LB-01) was produced on DotLiquid 2.3.260; Programme Reference v12 §13.4 recorded different tag trimming on the work-system build. Run HT-W3-1 before treating it as a production risk.
  • Samples not available. No raw Radar response for either product (responses were reconstructed from stored outputs); no real LB renewal (not live); no payload with an amended flood, storm, escape-of-water or breakdown excess; no LB contract. Affected findings are marked VALIDATE.
  • Not reviewed. Upstream Layer-2 items PRE_7200 and PRC-04 (need a production input/output pair); the 20.11 request-pair report findings RQ/RR/RO, held on the work system (aliases mapped where known).
