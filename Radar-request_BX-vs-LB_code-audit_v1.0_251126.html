In plain terms

In plain terms: three request templates reviewed: the BX NB/MTA request, the BX renewal request and the LB request. All three build valid Radar requests from real payloads only if the engine trims whitespace fully (syntax level 22) and the Function App decodes the base64 fields first; neither is documented or confirmed. The most serious template defect is that BX amended premises excesses never reach Radar: the gate tests the amount field instead of the Yes/No flag, proven on a real renewal. BX also never sends commission rate or agent, where LB does; LB never sends the residents-association flats question. Typed text with a quote breaks the request in both products. 16 fix groups are recommended for the next versions; the excess and commission-rate fixes change what Radar prices on and need Pricing sign-off. 12 contract questions go to Pricing, Instanda configuration and Integration.
